# Goal 工具按需展开设计与实测报告

在 Pi 1.7 父会话中，`pi-goal-x-lean` 首轮仅向模型暴露 `get_goal` 与 `goal` 两个工具声明，将常驻工具开销压缩至约 **200 token**（采用真实分词器统计，涵盖工具名、功能描述、参数 Schema 及常驻调用指引）。终端用户仍通过 `/goal`、`/goal-tweak`、`/goal-resume` 等斜杠命令无感操作目标。

## 按阶段渐进式披露

| 对话时机 | 向模型暴露的信息边界 |
| --- | --- |
| **普通对话首轮** | `get_goal` 支持直接读取目标进度；`goal` 列出可用操作名称，并提示如何按单个操作查询详细帮助。 |
| **用户发起起草或修订** | 当前阶段提示按需注入如何发起澄清问卷或提交目标草稿供用户确认。 |
| **执行常规更新** | 模型直接通过 `goal` 提交目标状态或里程碑变更，工具原样返回上游引擎执行结果。 |
| **涉及复杂参数结构** | 需要问卷结构、批量任务、严格等待等冷门约束时，模型针对具体操作调用 `help`，动态展开完整参数、校验规则与调用示例。 |

## 路由架构与隔离契约

- **七项上游操作全保真委派** — 上游全部七项操作均保留原始工具名、参数校验、事件派发、交互确认与完成审计。终端将路由调用渲染为一条统一的 `goal` 工具记录，直接调用 `get_goal` 则保持原生展示形态。`get_goal` 同时开放直接调用与 `goal` 路由调用，其余六项写/起草操作统一经由 `goal` 的 `op` 参数进入，通过 Pi 的 `ctx.executeTool()` 委派至原工具并完整透传返回正文、`details`、`terminate` 与错误标志；嵌套调用产生的 token usage 由 Pi 宿主统一汇总，包装层不重复计入。
- **仅隐藏声明、不改激活集** — `prepareLoadout` 仅从发往模型的工具声明列表中隐藏六项被路由工具，不改变底层活动工具集合，因此停止后的回合依然能够直接调用只读的 `get_goal`。
- **任务开关联动** — 当配置关闭任务跟踪时，上游不激活 `set_goal_tasks` 与 `update_goal_task`；路由器同步拒绝这两项调用，按需 `help` 不再列出它们，起草阶段的常驻说明也明确要求省略 `tasks`（若草稿目标本身包含编号条目，上游仍会按既有安装基线行为从中推导任务）。
- **分阶段精准提示** — 活跃目标提示“任务清单确认会结束当前回合并在用户确认后继续推进”；暂停状态下的目标仅提示只读 `get_goal` 与生命周期更新 `update_goal`。
- **会话角色隔离** — 父会话始终安装路由器与阶段提示（不再保留旧版全量直连工具分支）；委派目标会话与 subagent 子会话仅安装继承上下文过滤器，不安装路由器或任何目标写入入口。

## 真实请求体 Token 测量

测试在本地回环（loopback）拦截 Pi 1.7.0 发出的 OpenAI Chat Completions 规范化请求体，使用 `tiktoken==0.12.0` 的 `gpt-4o` 编码精确计数；对比基线为改造前已安装的 `0.1.4` 版本，测试过程固定模型回复并自动确认交互弹窗。普通对话首轮仅携带两个工具声明及内嵌简短说明；进入起草或执行阶段时，测试场景分别仅增加约 **69** 或 **115 token** 的阶段提示。

| 测量维度 | 旧基线（0.1.4） | 按需展开候选 |
| --- | ---: | ---: |
| 首轮普通请求总长度 | 2424 | 1372 |
| 普通首轮请求体净增量（启用 Goal 对比未启用） | 1248 | **196** |
| `read` 场景累计 | 4928 | 2824 |

| `taskRetry` 场景累计 | 17615 | 13334 |

```bash
/home/ubuntu/miniforge3/envs/codex/bin/python scripts/measure-goal-provider.py
```

## 真实模型自然语言演练

在四个相互独立的 Pi 1.7 父会话中直连真实服务调用 `gpt-6.2-sol`：用户输入仅描述业务目的，由模型自主挑选工具，测试宿主代答问卷并确认草稿。

- **常规状态读取** — 2 次模型请求完成。
- **任务创建、启动、完成与回读闭环** — 共 10 次模型请求完成。
- **复杂目标起草** — 模型主动按需查询问卷与提案两个主题的 `help`，4 次请求即完成草稿确认。
- **显式查文档起草（含自愈纠错）** — 模型首次误将帮助主题写成 JSON 对象字符串，收到明确的路由错误提示后立即改为纯主题名并顺利完成，共 5 次请求。

四场演练合计 **21 次请求**，服务端重试 **0 次**；重新打开会话后，任务完成证据、草稿目标内容及三个里程碑均完整持久化保留。
