# Goal 工具按需展开

Pi 1.7 的父会话只向模型声明 `get_goal` 和 `goal` 两个 Goal 工具，首轮约 200 token。计算使用真实分词器，范围包含工具名、描述、参数和常驻调用指引。用户仍通过 `/goal`、`/goal-tweak` 和 `/goal-resume` 等命令操作目标。

| 时机 | 模型需要的信息 |
| --- | --- |
| 普通对话 | `get_goal` 可直接读取进度。`goal` 列出操作，并说明如何针对一个操作查帮助。 |
| 用户发起起草或修改 | 当前步骤说明如何提问或提交草稿供确认。 |
| 执行常用操作 | 直接提交目标或任务更新，工具返回上游执行结果。 |
| 需要问卷结构、批量任务、严格等待等细节 | 针对具体操作请求帮助，展开参数、约束和调用示例。 |

## 路由

- 上游七项操作都保留原名称、参数校验、事件、确认和审计。终端把路由调用显示为一条 `goal` 工具记录，直接调用 `get_goal` 仍使用原显示方式。`get_goal` 同时直接可见；其余六项由 `goal` 的 `op` 调用，`get_goal` 也可经 `goal` 调用。写操作通过 Pi `ctx.executeTool()` 进入原工具，返回内容、`details`、`terminate` 和错误标志；嵌套调用的 usage 由 Pi 汇总，包装层不重复计入。
- `prepareLoadout` 只隐藏六项路由声明，不改变活动工具集合，所以停止后的回合仍可直接调用只读 `get_goal`。
- 任务关闭时，上游不激活 `set_goal_tasks` 和 `update_goal_task`；路由拒绝这两项，帮助也不再列出它们。起草阶段的常驻说明要求省略 tasks。上游仍会从带编号的草稿目标推导任务，这项行为与安装基线一致。
- 活跃目标提示任务清单确认会结束当前回合并在确认后继续；暂停目标只提示 `get_goal` 和 `update_goal`。
- 路由和阶段提示始终安装，不提供旧版直接工具路径。委派目标会话和 subagent 子会话只安装上下文过滤，不安装路由或目标写入路径。

## 测量

Pi 1.7.0 的 OpenAI Chat Completions 请求体经本机回环捕获，用 `tiktoken==0.12.0` 的 `gpt-4o` 编码计数。基线为已安装的 0.1.4。测试固定模型响应，并自动确认交互。表中报告规范化请求体的编码长度。普通首轮只有两个工具声明及其内嵌说明。进入起草或执行阶段时，示例场景分别增加约 69 或 115 token 的阶段提示。

| 首轮普通请求 | 2424 | 1372 |
| 普通首轮请求体增量（启用 Goal 相对未启用） | 1248 | **196** |

## 自然语言演练

四个独立的 Pi 1.7 父会话通过真实服务调用 `gpt-6.2-sol`。用户请求只描述目的，模型自行选择工具，测试宿主代答问卷并确认。普通读取用了 2 次模型请求，任务创建、开始、完成和读回共 10 次。复杂草稿中，模型自行查询问卷和提案两个主题的帮助，4 次请求完成确认。另一场明确要求查文档的草稿中，模型先把帮助主题写成 JSON 对象字符串，收到错误后改为主题名称，合计 5 次请求。四场共 21 次请求，服务重试 0 次。重新打开会话后，任务证据、草稿目标及三个里程碑均已保存。
