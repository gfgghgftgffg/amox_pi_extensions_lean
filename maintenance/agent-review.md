## Findings and minimal adaptation

- No tool or action removed or added: todo still has create/update/list/get/delete/clear, required action. New optional tasks array has items requiring subject, with optional description/activeForm/blockedBy/owner/metadata. Existing defaults remain: pending create, includeDeleted=false, clear nextId=1. The facade retains upstream schema including nested batch items and recursively strips descriptions while preserving actual description input fields.
- Batch create is atomic, requires nonempty tasks or subject exclusively, rejects top-level per-item fields and dependencies on other members of the batch, and permits dependencies on existing nondeleted tasks. The new upstream prepareArguments decodes string arrays and string object items before validation. The existing facade already calls upstream's hook before its local inference. No new action inference is introduced: batches require explicit action=create.
- Changed local description from create needs subject to subject or tasks[]. Extended the existing single guideline with batch syntax, atomic behavior, per-item fields and dependency constraints; all existing rules remain. No upstream implementation copied, no local reducer or normalization implementation added.
- Reducer create op now exposes taskIds instead of taskId; local facade does not consume this internal result. Actual tool output is content text (one Created line per item) and details containing params, full tasks snapshot and nextId, plus error on failure. It does not gain structuredContent or a reducer isError flag. Batch success writes one rpiv-todo-state entry; rejection writes none. Single-create text remains compatible.
- Delegated renderCall displays batch count and omits undefined for absent action. Delegated renderResult shows a failure glyph and first error line when details.error or host context.isError indicates failure, instead of echoing requested status as success. Model-facing errors are unchanged.
- Replay now validates each task's required and optional fields plus safe-integer IDs/nextId, skipping malformed snapshots whole and retaining the latest valid snapshot. Custom-entry priority and legacy tool-result fallback remain. RPC lifecycle handlers call this same replay implementation, so they inherit the resume fix.
- Reviewed upstream index/overlay/store/config/bridge interfaces remain compatible: ordinary private overlay fields and getSnapshot patch, methods, session slot functions, events, command, shortcut, optional i18n loader and live scope boundary. Existing RPC isolation, stale guards and async command settlement remain.

Updated existing bilingual todo README usage and runtime version. Detailed adaptation history is in package MAINTENANCE, with current character proxies generated by check rather than copied from another environment.

## Verification and blocker

Added only packages/rpiv-todo-lean/tests/upstream-215-regression.test.mjs. Tests use the real facade/runtime, isolate config before imports, validate normalized inputs against the real schema, and cover batch data fields, double encoding, atomic rejection, existing dependencies, single persistence entry, RPC lifecycle replay after a corrupt snapshot, and delegated batch/error rendering. Assertions distinguish model text, details snapshots and rendered cards. There are no new network regressions or unrelated upstream tests. All baseline assertions remain untouched.

The existing append-only wrapper.test.mjs asserts the exact obsolete description, an exact field list without tasks, and metadata length <=1200. Those requirements conflict with exposing the new upstream batch schema and accurately describing it. Do not hide tasks or intercept test behavior to manufacture a pass. check is run for actual evidence; this candidate cannot be declared ready if those protected assertions fail. Resolving this policy/contract conflict requires a maintainer decision.

No successful result is presumed. Character proxies are not billing tokens. Interactive terminal behavior, live services and three-platform CI remain outside this local verification.
