# Source review

## amox-pi-sync pruning and deletion propagation

- Comparison base: `37d1061b9a951313b9cd28a8eec4380c84ac26ec`. This is a local feature addition; upstream remains `pi-sync-suite@0.1.1` and no upstream runtime is used or executed.
- `core.ts` adds `pruneOrphanSessionsBeforePush` and `syncedPaths`. The latter is a per-device baseline of managed paths present at the last successful Push/Pull. A missing baseline is seeded at session start from the intersection of local and existing snapshot paths, without reading file bodies. Local-only and unpulled remote-only paths stay outside it; before a baseline exists, Push never deletes snapshot-only files and Pull applies the whole snapshot. This avoids deleting remote files that were never pulled while allowing a file present on both sides to propagate a later local deletion immediately.
- Push removes only baseline paths that are now missing locally, stages them with `git add -A --` in bounded batches, and commits before pushing. Pull computes remote deletions as baseline paths absent from the new snapshot, deletes local copies after one recovery backup, and preserves locally missing baseline paths as pending deletions so a later Push can propagate them. Active sessions cannot be deleted. Files never synced remain local-only.
- Orphan selection is a pure fixed-point function over header `parentSession` and the last `session_info` name. Parent lookup uses a lower-cased basename after normalising both separators, so moved `~/.pi` roots and Windows paths do not invalidate parents. Names must match `type#8hex`. Duplicate parent basenames are treated as ambiguous and never deleted. Recent files (10 minutes) and the active session are protected; descendants of protected files are not selected.
- `planPruneSessions` is read-only and takes no service lock. `pruneOrphanSessions` takes the lock, rechecks candidates before touching the snapshot, refuses staged or uncommitted repository changes, deletes snapshot copies first, commits `amox-pi-sync: prune N orphan subagent session(s)`, then deletes local files. It refuses symlinks and non-files, accepts an optional confirmed path set so a preview cannot widen, and removes pruned paths from `syncedPaths`. No full backup is created by default; the snapshot Git history retains the removed copies.
- UI adds a Prune orphan sessions action with count/size/first-name preview and confirmation, a default-Off `Prune before push` setting, and `/sync-prune [--yes]`. Manual Push, `/sync-push` and automatic Push route through `pushWithPrune` before `run("Push")`, so the pre-push fingerprint already includes deletions. Prune failures warn and do not block Push. `/sync-setup` preserves the setting but deliberately does not carry a baseline to a different repository.
- Real Git regressions cover manual deletion propagation through Push/Pull, prune followed by Push and a later Pull without resurrection, disjoint divergence, conflicting divergence and byte-preserving EOL handling. Unit/UI regressions cover the selection rules, recent/active/ambiguous guards, snapshot-first prune, dirty-repository refusal, preview confirmation, `--yes`, before-push ordering and non-blocking prune failure.

Status bubbles now summarize replaced-file lists as the first three paths plus `(+N more)` and cap each rendered row to 160 characters. Full action results remain in notifications; actions stay reachable without scrolling.

Pull and restore backups are now partial: only the local files being replaced or deleted are copied, with a `files` manifest; a pull that adds only new files creates no backup. Manual Create backup remains a full managed-data snapshot. Cleanup still counts complete backup directories and remains manual.

Local verification: sync typecheck and all 72 package tests, the full repository test suite, scoped contracts and isolated production installation/loading. Dependency audits completed with upstream warnings (production: 6 affected packages, including 2 high-severity findings); this patch adds no dependency. Release batch `0.1.25` selects only `amox-pi-sync@0.1.9`, based on `37d1061b9a951313b9cd28a8eec4380c84ac26ec`. Other package versions and publication files are unchanged.
