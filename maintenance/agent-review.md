## Contract changes and minimal adaptation

- The same four business tools and five-argument execute contract remain. Search adds optional `model`; fetch adds opt-in `extract` and conditional `fields`. Required fields and existing defaults remain unchanged: search count 5, workflow none, fetch readable, allowed fetch modes readable/raw/answer. Runtime dependencies and peers are unchanged. Keep the resident facade schema as op/input; disclose advanced additions through real help and JSON forwarding.
- Upstream provider schema is now a string with comma-separated names, and unknown names fail strictly. Runtime parsing still accepts legacy arrays and JSON arrays. Its prepareArguments no longer normalizes provider. Preserve the existing facade normalization contract by calling upstream parseStringifiedArrays for provider before delegating the captured hook. No parsing implementation is copied and baseline assertions are retained.
- Compact upstream help no longer lists provider names. On-demand search/check help reads upstream getAllowedSearchProviders, including ninerouter and respecting the configured allowlist. No hardcoded inventory or additional resident schema is introduced. The two internal module helpers are now explicit upgrade dependencies, loaded on demand; existing entry/PDF type stub boundaries are retained.
- Per-call search model needs exactly one explicit OpenAI/xAI/Mistral/Gemini provider, Gemini API only; summary-review rejects it. Failures do not retry other models. 9router requires a base URL, calls base/search, defaults its backend to serper and has optional auth; auto/all exclude it.
- Extract actually uses fetch.allowedModes (one changelog line says fetchContent.allowedModes). It remains off by default and cannot be the default mode. Fields are validated before fetch; auth is rejected. Cloudflare Clairic uses Pi provider credentials and receives fetched page text, including signed-in GitHub text when applicable. Upstream owns confidence/type/source-line checking. The local PDF direct path now explicitly rejects extract instead of silently ignoring fields; remote PDFs use upstream extraction. No expansion of the existing local PDF answer path is attempted.
- Extract rendered text contains field values/uncertainty and storage hints. structuredContent.urls[].extraction contains typed fields or an extraction error; urls[].content and get retain original page text. A successful fetch with failed field extraction is still stored and need not be isError. Preserve results intact, without hint rewriting.
- Source check now renders passages (up to 4000 characters per source), with claim-first matching, short acronym/number matching and dotted-host sentence preservation. details.artifact remains the research data; no automated semantic verdict is claimed.
- Routed searches can fall through empty/domain-miss/off-topic results, with configured classifier for off-topic, and a total 1–600000 ms budget including availability checks. Exhausted routes return the first skipped success when available. DuckDuckGo serializes searches two seconds apart and cools down after bot checks; its deadline includes queuing and reports network failure for fallback.
- Helper selectors support current[:level] or provider/model-id[:level]. Explicit summary selection never switches to another cloud model; it returns a deterministic fallback with a reason on failure, while invalid selectors error. Explicit query rewrite selection is also strict. Scope checks remain. The new session-start upgrade notice is delegated; fresh install/downgrade does not notify.
- Bilingual user docs update current provider/model/extract usage, output distinctions, HTTP gateway opt-in, Azure/Exa configuration and helper-model behavior. Measurements and current versions are refreshed by check, using ceil(characters/4), not billing tokens. Detailed history stays in MAINTENANCE.
